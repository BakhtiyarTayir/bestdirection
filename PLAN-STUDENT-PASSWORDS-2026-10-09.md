# План: администратор видит логин и пароль ученика — 2026-10-09

Клиент хочет раздавать ученикам доступы: администратор открывает ученика,
копирует логин и пароль и передаёт ему. Сейчас пароль хранится только
необратимым отпечатком (`User.passwordHash`, bcrypt) — текущие пароли
узнать нельзя никак. Поэтому пароль запоминается в момент, когда он
задаётся, в обратимо зашифрованном виде.

## 0. Решения владельца (2026-10-09) — не пересматривать

- Небезопасность владелец понимает и принимает: администратор видит пароль.
- **Только ученики** (role STUDENT). Пароли персонала и родителей не
  сохраняются и не показываются.
- **Сохраняется любой пароль ученика**: и заданный администратором, и
  сменённый самим учеником (профиль, сброс через Telegram).
- **Существующие ученики**: массовая кнопка «Выдать пароли тем, кто ни разу
  не входил» + по одному кнопкой «Задать пароль». Вошедших массово не трогаем.
- Видит и меняет только администратор (`manage User`/ADMIN). Преподаватель,
  ученик, родитель — нет, проверка на сервере.

## 1. Хранение

- Новое поле `User.passwordEnc String?` — AES-256-GCM, формат
  `v1:<iv b64>:<tag b64>:<ciphertext b64>`. Миграция только добавляет колонку
  (ничего не удаляет).
- Ключ выводится из `INTERNAL_TOKEN` (HKDF/sha256 с меткой
  `"student-password-view"`) — тот же приём, что секрет в
  `api/src/modules/notifications/sms.service.ts`; новой переменной
  окружения на сервере не нужно. Утечка одной базы паролей не раскрывает.
- Модуль `api/src/common/security/password-vault.ts`: `sealPassword(plain)`,
  `openPassword(enc)` → строка или null (битые данные/сменённый ключ — null,
  не исключение). Unit-тест: круговой путь, подмена байта → null.
- Везде, где ученику пишется `passwordHash`, рядом пишется `passwordEnc`
  (только STUDENT); у не-учеников `passwordEnc` всегда null. Найти все
  места записи `passwordHash` (`users.service.ts`, `auth.service.ts`,
  `parents.service.ts` и др.) и пройти каждое; смена роли с STUDENT на другую
  обнуляет `passwordEnc`.
- В аудит, логи и обычные ответы API пароль не попадает (в т.ч. в
  `computeChanges` — `passwordEnc` исключить, как `passwordHash`).

## 2. Последний вход

- Новое поле `User.lastLoginAt DateTime?`, ставится при успешном входе
  (пароль и Telegram). Миграция заполняет его из `Session` (самая ранняя
  `createdAt` по пользователю) — сессии хранятся 30 дней, самая старая на
  проде от 2026-09-21, но выход из системы сессию удаляет, поэтому
  заполнение неполное: это учтено в массовой кнопке (предпросмотр).
- «Ни разу не входил» = `lastLoginAt IS NULL` И нет ни одной `Session`.

## 3. API (только ADMIN)

- `GET /users/:id/credentials` → `{ login, password: string | null, state }`,
  `state`: `known` | `unknown` (пароль задан до этой функции — нужно
  задать заново). Только для STUDENT, иначе 404. Пишет в аудит факт
  просмотра (`action: "UPDATE"` нельзя — завести `metadata: {
  viewedPassword: true }` по образцу существующих записей; без пароля).
- `POST /users/:id/password` `{ password? }` — задать пароль ученику (пусто
  — сгенерировать). Ответ: `{ login, password }`.
- `GET /users/students/never-logged-in?branchId=` — предпросмотр: список
  (фамилия, имя, логин, филиал) и количество.
- `POST /users/students/issue-passwords` `{ studentIds: string[] }` —
  выдаёт КАЖДОМУ свой случайный пароль (не один общий), только тем, кто
  по-прежнему подходит под «ни разу не входил» (повторная проверка на
  сервере). Ответ: список `{ fullName, login, password, branch }`. Одна
  транзакция; аудит по каждому без пароля.
- Генератор: 8 символов, без похожих (0/O, 1/l/I), буквы + цифры,
  `crypto.randomInt`.
- Существующие сессии ученика при смене пароля администратором НЕ
  сбрасываем (он мог уже работать на телефоне) — решение можно поменять.

## 4. Web (только ADMIN)

- Карточка/редактирование ученика: блок «Доступ»: Логин [копировать],
  Пароль `••••••` [показать] [копировать] либо «Пароль неизвестен — задайте
  новый»; кнопка «Задать пароль» (диалог: поле с кнопкой «Сгенерировать»,
  после сохранения — показать логин+пароль и «Скопировать всё» одним
  текстом `Логин: … Пароль: …`).
- Список учеников: кнопка «Выдать пароли» → диалог предпросмотра (кто
  попадёт, фильтр по филиалу, галочки) → после выдачи таблица логин–пароль,
  кнопки «Скопировать» и «Скачать CSV».
- Пароль загружается только по нажатию «показать» (отдельный запрос), в
  списке учеников пароли не подгружаются.
- ru и uz, 360px.

## 5. Тесты

- Права: TEACHER/STUDENT/PARENT — 403/404 на все маршруты; ADMIN — 200.
- Создание ученика с паролем → credentials отдаёт тот же пароль; вход с
  ним работает.
- Ученик сменил пароль в профиле / через Telegram-сброс → credentials
  отдаёт новый.
- Учитель/родитель: `passwordEnc` остаётся null.
- Массовая выдача: вошедший (есть сессия или lastLoginAt) пропускается даже
  если его id прислали; у каждого свой пароль; вход работает.
- Пароль нигде не попадает в AuditLog (проверить строкой).
- password-vault: unit.
