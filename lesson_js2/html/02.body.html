this
и контекст вызова

В уроке 8 первого курса мы договорились: this — это «текущий объект». Формулировка рабочая, но неполная. Одна и та же функция при разных формах вызова получает разный this — и на этом ломаются обработчики, колбэки и таймеры.

01

Проблема

Функция одна и та же. Меняется только способ вызова — и this меняется вместе с ним.

const user = {
  name: "Али",
  sayHi() {
    console.log("Привет, я " + this.name);
  }
};

user.sayHi();                 // "Привет, я Али" — работает

const greet = user.sayHi;     // взяли ту же функцию в переменную
greet();                      // "Привет, я undefined" 😱
Демо · одна функция, два вызова Нажмите обе кнопки и сравните вывод
Вызовите функцию любым из двух способов

Ключевое правило урока

this определяется не там, где функция объявлена, а там, где она вызвана. Этим он отличается от обычных переменных: их функция берёт из лексического окружения (урок 1), а this получает заново при каждом вызове.

03
Потеря контекста: три сценария

  
Это 90% всех багов с this. Каждый сценарий — в отдельном демо.


  
Сценарий 1. Метод передали как колбэк

  
Метод оторвали от объекта и передали как значение — колбэк вызывается обычным вызовом, объект потерян. Так ломаются forEach, addEventListener и таймеры из следующего урока.



const timer = { name: "Таймер", start() { console.log(this.name); } };

[1].forEach(timer.start);              // ❌ undefined
[1].forEach(() => timer.start());       // ✅ Таймер
[1].forEach(timer.start.bind(timer));  // ✅ Таймер

Сценарий 3. Стрелочная функция как метод

  
Обратная ошибка — ею мы уже пугались в первом курсе. У стрелки нет своего this, она берёт его из окружающего кода, а вокруг литерала объекта лежит внешняя область, а не сам объект.



const user = {
  name: "Али",
  sayHi: () => console.log(this.name)  // ❌ undefined
};


  

    Короткое правило. Метод объекта — обычная функция. Всё, что вызывается внутри метода, — стрелочная.
  






  
04
call, apply и bind

  
Все три позволяют задать this явно. Разница — в моменте вызова и в форме аргументов.



function introduce(city, job) {
  console.log(`${this.name}, ${city}, ${job}`);
}

introduce.call(ali, "Ташкент", "разработчик");      // аргументы через запятую
introduce.apply(gulya, ["Самарканд", "дизайнер"]);  // аргументы массивом

const introduceAli = introduce.bind(ali);           // НЕ вызывает — создаёт функцию
introduceAli("Ташкент", "разработчик");

05
this в обработчиках событий

  
В обработчике-обычной функции this — это элемент, на котором висит обработчик. В стрелочной — берётся снаружи, поэтому элемент достают из события.



btn.addEventListener("click", function () {
  this.classList.toggle("active");              // this = сама кнопка
});

btn.addEventListener("click", (event) => {
  event.currentTarget.classList.toggle("active");  // надёжнее
});

08
Вопросы с собеседований

  
Отвечайте вслух, потом раскрывайте ответ.


  
Что такое this и когда оно определяется?
    
Ссылка на контекст выполнения функции. Определяется в момент ВЫЗОВА, а не при объявлении: одна и та же функция при разных формах вызова получит разный this. Этим он отличается от обычных переменных, которые берутся из лексического окружения.

  


  
Перечислите правила определения this.
    
Обычный вызов fn() — undefined в strict mode (в нестрогом — глобальный объект). Вызов как метода obj.fn() — объект перед последней точкой. Явная привязка call/apply/bind — переданный объект. Вызов через new — новый создаваемый объект. Отдельно: у стрелочных функций своего this нет, они берут его из окружающего кода.

  


  
В чём разница между call, apply и bind?
    
call и apply вызывают функцию немедленно с указанным контекстом; отличаются формой передачи аргументов: call — через запятую, apply — массивом. bind не вызывает функцию, а возвращает новую с навсегда привязанным контекстом (и, если нужно, с заранее подставленными аргументами).

  


  
Что такое потеря контекста? Приведите пример.
    
Ситуация, когда метод отрывают от объекта и вызывают отдельно — контекст перестаёт быть объектом. Классика: setTimeout(user.greet, 1000) или arr.forEach(user.greet) — метод передан как значение и вызывается обычным вызовом. Лечится обёрткой в стрелочную функцию или bind.

  


  
Почему методы объекта не пишут стрелочными функциями?
    
У стрелочной функции нет собственного this — она берёт его из окружающего лексического окружения. Для метода, объявленного прямо в литерале объекта, окружением будет внешний код, а не сам объект, поэтому this.name даст undefined. Обратная ситуация — колбэк внутри метода: там стрелочная функция как раз нужна.

  


  
Чему равен this в обработчике события?
    
В обработчике-обычной функции this — это элемент, на котором висит обработчик (то же, что event.currentTarget). В стрелочном обработчике this берётся из внешнего кода, поэтому к элементу обращаются через event.currentTarget. Второй вариант предсказуемее.

  


  
Практическая задача: что выведет showRegular и showArrow?
    
showRegular выведет undefined A и undefined B: колбэк — обычная функция, вызванная внутри forEach обычным вызовом, поэтому у неё свой this, равный undefined.
showArrow выведет Магазин A и Магазин B: у стрелочной функции своего this нет, она берёт его у метода showArrow, а тот вызван через точку от shop. Проверьте это в демо раздела 03.
