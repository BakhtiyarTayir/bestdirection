01

Функция высшего порядка

В первом курсе мы уже передавали функции внутрь других функций — filter, map, reduce. Теперь назовём это точнее.

Функция высшего порядка — функция, которая делает хотя бы одно из двух: принимает другую функцию как аргумент или возвращает функцию как результат. Первое мы умеем. Второе — новое.

function makeGreeter(greeting) {
  return function (name) {
    console.log(`${greeting}, ${name}!`);
  };
}

const salom = makeGreeter("Салом");
const hello = makeGreeter("Hello");

salom("Али");   // "Салом, Али!"
hello("Bobur"); // "Hello, Bobur!"

Обратите внимание: makeGreeter("Салом") не печатает ничего — она возвращает функцию, которую мы сохранили и вызвали позже. Вызовов получилось два: один создаёт, второй выполняет. Можно и сразу, в две пары скобок: makeGreeter("Привет")("Гуля").

Главный вопрос урока

Посмотрите на salom внимательно. Функция makeGreeter уже завершилась — её переменные должны были исчезнуть. Но salom("Али") всё ещё знает, что greeting это «Салом».

makeGreeter("Салом") вызвана → создала функцию → ЗАВЕРШИЛАСЬ
                                    ↓
                      а функция всё ещё помнит greeting = "Салом"

Как? Ответ — замыкание.

03

Лексическое окружение

Вспомним scope chain из урока 10 первого курса: JS ищет переменную изнутри наружу. Ключевая деталь, которую мы тогда не проговорили:

Функция запоминает то место, где она была объявлена, а не то, откуда её вызвали. Это называется лексической областью видимости: при создании к функции «прикрепляется» ссылка на внешнее окружение — набор переменных, которые её окружали.

const lang = "глобальный";

function outer() {
  const lang = "из outer";
  return function inner() {
    console.log(lang); // смотрит туда, где inner была ОБЪЯВЛЕНА
  };
}

const fn = outer();
fn(); // "из outer" — хотя вызвали её из глобальной области

Определение

Замыкание (closure) — функция вместе с сохранённым внешним окружением. Пока живёт функция, живут и переменные, которые ей нужны: сборщик мусора не удалит их, даже если внешняя функция давно завершилась. В JavaScript замыкание образует каждая функция — просто обычно мы этого не замечаем.

04

Счётчик: канонический пример

Каждый вызов внешней функции создаёт новое независимое замыкание. Создайте два счётчика и убедитесь сами: у каждого своя переменная count, снаружи её не достать.

function makeCounter() {
  let count = 0;        // переменная живёт в замыкании

  return function () {
    count++;
    return count;
  };
}

05

Приватные данные

Из урока 8 первого курса вы помните: свойства объекта доступны снаружи, испортить их может кто угодно — account.balance = -999999, и никто не помешал. Замыкание даёт настоящую приватность.

function createAccount(owner, startBalance = 0) {
  let balance = startBalance;   // приватная переменная

  return {
    deposit(sum) {
      if (sum <= 0) return "Сумма должна быть больше нуля";
      balance += sum;
      return balance;
    },
    withdraw(sum) {
      if (sum > balance) return "Недостаточно средств";
      balance -= sum;
      return balance;
    },
    check() {
      return owner + ": " + balance;
    }
  };
}

Это тот самый «Банкомат» из первого курса — теперь у приёма есть имя. Такая конструкция называется модульным паттерном: наружу выставлены только методы, состояние спрятано.

IIFE — функция, вызванная сразу

Иногда замыкание нужно один раз и без имени. Тогда функцию объявляют и тут же вызывают:

const config = (function () {
  const apiKey = "секрет";        // снаружи недоступен
  let requests = 0;

  return {
    makeRequest() {
      requests++;
      return `Запрос №${requests} с ключом ${apiKey}`;
    }
  };
})();  // ← скобки в конце вызывают функцию немедленно

console.log(config.makeRequest()); // "Запрос №1 с ключом секрет"
console.log(config.apiKey);        // undefined

IIFE — Immediately Invoked Function Expression, «немедленно вызываемое функциональное выражение». До появления модулей так изолировали код целых библиотек. Сегодня встречается в основном в чужом коде — важно узнавать.

Одна фабрика — сколько угодно специализированных функций. Каждая помнит свой множитель.

Выполнить только один раз

Так защищают от двойной отправки формы по двойному клику: флаг живёт в замыкании.

function once(fn) {
  let called = false;
  let result;

  return function (...args) {
    if (called) return result;
    called = true;
    result = fn(...args);
    return result;
  };
}

Мемоизация — запоминание результатов

Хранилище результатов живёт в замыкании. Первый вызов считает долго, повторный — мгновенно берёт из кэша.

function memoize(fn) {
  const cache = {};                 // хранилище в замыкании

  return function (n) {
    if (n in cache) return cache[n];
    cache[n] = fn(n);
    return cache[n];
  };
}

Почему так

    
У var нет блочной области видимости, поэтому i одна на весь цикл. Все три функции замкнулись на одну и ту же переменную, а к моменту вызова она давно равна 3. let создаёт новую переменную на каждой итерации — и каждая функция замыкается на свою. Вот и ещё один аргумент против var, теперь понятный до конца.

Вопросы с собеседований

  
Отвечайте вслух, потом раскрывайте ответ.


  
Что такое замыкание?
    
Замыкание — функция вместе с сохранённым внешним лексическим окружением. Функция запоминает переменные того места, где была объявлена, и продолжает иметь к ним доступ даже после того, как внешняя функция завершилась. В JavaScript замыкание образует каждая функция, просто чаще всего это незаметно.

  


  
Что такое функция высшего порядка?
    
Функция, которая принимает другую функцию как аргумент и/или возвращает функцию. Примеры из стандартной библиотеки — map, filter, reduce, addEventListener. Это возможно потому, что функции в JS — обычные значения, которые можно передавать и возвращать.

  


  
Зачем нужны замыкания на практике?
    
Приватные данные и модульный паттерн (состояние спрятано, наружу выставлены методы), фабрики функций, мемоизация и кэширование, функции-обёртки вроде once, debounce, throttle, а также счётчики и любое сохранение состояния между вызовами без глобальных переменных.

  


  
Будут ли счётчики, созданные одной фабрикой, независимы?
    
Да. Каждый вызов внешней функции создаёт новое лексическое окружение, поэтому у каждого счётчика своя переменная. Общим остаётся только устройство «по чертежу», данные не пересекаются.

  


  
Что такое IIFE и зачем оно нужно?
    
Immediately Invoked Function Expression — функция, которая объявляется и тут же вызывается: (function () { … })(). Создаёт изолированную область видимости, чтобы переменные не попали в глобальную. До появления ES-модулей это был основной способ изолировать код библиотеки; сегодня используется редко, но часто встречается в старом коде.

  


  
Могут ли замыкания привести к утечке памяти?
    
Да. Пока существует функция-замыкание, сборщик мусора не может освободить переменные, на которые она ссылается. Если такая функция висит в долгоживущем обработчике события или в таймере и удерживает большой объект, память не освободится. Лечится снятием обработчика и очисткой ссылок, когда они больше не нужны.

  


  
Практическая задача: почему выводится 3 3 3 и как починить?
    
var не имеет блочной области видимости — переменная i одна на весь цикл, и все три функции замкнулись именно на неё. К моменту вызова цикл давно закончился и i равна 3.
Починка: заменить var на let — тогда на каждой итерации создаётся отдельная переменная и каждая функция замыкается на свою копию. Исторический вариант до ES6 — обернуть тело цикла в IIFE с параметром.
