01

setTimeout — выполнить позже

Первый аргумент — функция (снова колбэк), второй — задержка в миллисекундах: 1000 мс = 1 секунда. Программа не останавливается и не ждёт: она регистрирует задачу «выполнить позже» и идёт дальше.

setTimeout(function () {
  console.log("Прошла секунда");
}, 1000);

console.log("Эта строка выведется ПЕРВОЙ");

Аргументы для колбэка передаются третьим и далее: setTimeout(greet, 2000, "Али", "Салом").

Частая ошибка — вызвать функцию вместо того, чтобы передать её. setTimeout(greet("Али"), 2000) выполнит greet немедленно и передаст таймеру её результат. Правильно: setTimeout(() => greet("Али"), 2000). Та же ловушка, что с колбэками в map и forEach: скобки означают вызов.

02

Задержка — это «не раньше чем»

Даже с нулевой задержкой колбэк выполнится после текущего кода. JavaScript однопоточен: сначала доделывается всё, что выполняется сейчас, и только потом берётся отложенная задача.

Демо · порядок вывода Что напечатается первым? 
console.log("A");
setTimeout(() => console.log("B"), 0);
for (let i = 0; i < 3; i++) console.log(i);
console.log("C");
Нажмите «Запустить»

Следствие

Если основной код занят тяжёлым циклом, таймер опоздает — вторая кнопка это показывает: задержка была 0 мс, а колбэк выполнился только после цикла. Задержка гарантирует минимум, а не точность. Почему это так устроено — тема урока про event loop в третьем разделе.

Практический вывод: не полагайтесь на setInterval при отсчёте времени. Секундомер, который просто прибавляет по единице каждые 1000 мс, за минуту заметно уплывёт. Правильно — запомнить время старта и каждый тик считать разницу.

const start = Date.now();                // миллисекунды с 1970 года

setInterval(() => {
  const seconds = Math.floor((Date.now() - start) / 1000);
  console.log(seconds);                // всегда точно
}, 1000);
03

setInterval — повторять

setInterval работает бесконечно, пока его не остановят через clearInterval. Всегда сохраняйте идентификатор и всегда предусматривайте условие остановки — забытый интервал так же опасен, как бесконечный цикл while.

04

Рекурсивный setTimeout

Второй способ повторения — таймер, который в конце планирует сам себя. Разница видна, когда колбэк выполняется дольше интервала.

function tick() {
  console.log("тик");
  setTimeout(tick, 1000);   // планируем следующий ПОСЛЕ завершения
}
setTimeout(tick, 1000);

05

this в таймере

Помните потерю контекста из прошлого урока? Таймер — её главный источник: колбэк вызывается обычным вызовом, объект теряется.

const user = {
  name: "Али",
  greetLater() {
    setTimeout(function () {
      console.log("Привет, " + this.name);   // ❌ undefined
    }, 1000);
  }
};

// ✅ стрелочная берёт this у метода:
setTimeout(() => console.log("Привет, " + this.name), 1000);

// ❌ метод, переданный напрямую, теряет объект:
setTimeout(user.greetLater, 1000);
setTimeout(() => user.greetLater(), 1000);         // ✅
setTimeout(user.greetLater.bind(user), 1000);      // ✅
06

debounce — «подожди, пока перестанут»

Пользователь печатает «телефон» — событие input срабатывает 7 раз. Делать 7 запросов не нужно, нужен один — когда человек закончил печатать.

function debounce(fn, delay) {
  let timerId = null;                  // живёт в замыкании (урок 1)

  return function (...args) {
    clearTimeout(timerId);           // отменяем предыдущий план
    timerId = setTimeout(() => fn(...args), delay);
  };
}

Обратите внимание, как складываются темы раздела: замыкание хранит timerId, стрелочная функция сохраняет контекст, таймер откладывает вызов.

07

throttle — «не чаще, чем раз в N»

Задача другая: обработчик прокрутки срабатывает сотни раз в секунду. Ждать тишины нельзя — нужно реагировать, но реже. throttle пропускает вызов и на заданное время блокирует следующие.

function throttle(fn, delay) {
  let isWaiting = false;

  return function (...args) {
    if (isWaiting) return;             // ещё рано — игнорируем
    fn(...args);
    isWaiting = true;
    setTimeout(() => { isWaiting = false; }, delay);
  };
}

09

Вопросы с собеседований

Отвечайте вслух, потом раскрывайте ответ.

Чем setTimeout отличается от setInterval?

setTimeout планирует одно выполнение через заданную задержку, setInterval — повторяет вызов каждые N миллисекунд, пока его не остановят через clearInterval. Оба возвращают идентификатор таймера, по которому его можно отменить.

Гарантирует ли setTimeout(fn, 100), что функция выполнится ровно через 100 мс?

Нет. Задержка означает «не раньше чем»: колбэк попадёт в очередь через 100 мс, но выполнится только тогда, когда освободится основной поток. Если в этот момент выполняется тяжёлый синхронный код, вызов опоздает. Даже setTimeout(fn, 0) выполняется после завершения текущего кода.

Чем рекурсивный setTimeout лучше setInterval?

setInterval отсчитывает паузу от старта предыдущего вызова, поэтому при долгом колбэке вызовы «слипаются» и идут подряд. Рекурсивный setTimeout планирует следующий запуск только после завершения текущего — пауза соблюдается всегда. Плюс он позволяет менять задержку на каждом шаге, что нужно при повторных попытках запроса.

Что произойдёт, если не вызвать clearInterval?

Интервал продолжит работать до перезагрузки страницы — даже если элемент, ради которого он запускался, уже удалён. Это лишняя нагрузка и источник утечек памяти: колбэк держит замыкание со всеми переменными, на которые ссылается. Идентификатор интервала нужно сохранять и очищать, когда он больше не нужен.

Что такое debounce и throttle? В чём разница?

Обе техники ограничивают частоту вызовов. debounce откладывает вызов и сбрасывает отсчёт при каждом новом событии — функция сработает один раз, когда события прекратятся; подходит для поиска и автосохранения. throttle вызывает функцию сразу и затем блокирует вызовы на заданное время — она срабатывает регулярно, но не чаще N миллисекунд; подходит для scroll и mousemove.

Почему this внутри setTimeout не работает как ожидается?

Таймер вызывает переданный колбэк обычным вызовом, без объекта — срабатывает первое правило определения this, и контекст теряется. Решения: стрелочная функция (берёт this из окружения) или bind при передаче метода.

Практическая задача: что выведет код и почему?

Для кода console.log("A"); setTimeout(() => console.log("B"), 0); for (…) console.log(i); console.log("C"); вывод будет: A, 0, 1, 2, C, B.

Даже с нулевой задержкой колбэк не выполняется сразу: он попадает в очередь и берётся оттуда, только когда закончится весь текущий синхронный код. Поэтому B выводится последним. Проверьте это в демо раздела 02.
