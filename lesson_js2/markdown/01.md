## 1. Функция высшего порядка

В первом курсе мы уже передавали функции внутрь других функций — `filter`, `map`, `reduce`. Теперь назовём это точнее.

**Функция высшего порядка (higher-order function)** — функция, которая делает хотя бы одно из двух:
1. принимает другую функцию как аргумент;
2. возвращает функцию как результат.

Первое мы умеем:

```javascript
const nums = [1, 2, 3, 4];
nums.filter(n => n % 2 === 0);  // filter — функция высшего порядка
```

Второе — новое. Функция может **вернуть другую функцию**:

```javascript
function makeGreeter(greeting) {
    return function (name) {
        console.log(`${greeting}, ${name}!`);
    };
}

const salom = makeGreeter("Салом");
const hello = makeGreeter("Hello");

salom("Али");   // "Салом, Али!"
hello("Bobur"); // "Hello, Bobur!"
```

Обратите внимание: `makeGreeter("Салом")` не печатает ничего — она **возвращает функцию**, которую мы сохранили в переменную и вызвали позже. Вызовов получилось два: `makeGreeter(...)` создаёт, `salom(...)` выполняет.

Можно и сразу, в две пары скобок:

```javascript
makeGreeter("Привет")("Гуля"); // "Привет, Гуля!"
```

## 2. Главный вопрос урока

Посмотрите на `salom` внимательно. Функция `makeGreeter` уже **завершилась** — её переменные должны были исчезнуть. Но `salom("Али")` всё ещё знает, что `greeting` — это `"Салом"`.

```
makeGreeter("Салом") вызвана → создала функцию → ЗАВЕРШИЛАСЬ
                                     ↓
                       а функция всё ещё помнит greeting = "Салом"
```

Как? Ответ — замыкание.

## 3. Лексическое окружение

Вспомним scope chain из урока 10 первого курса: JS ищет переменную изнутри наружу. Ключевая деталь, которую мы тогда не проговорили:

**Функция запоминает то место, где она была ОБЪЯВЛЕНА, а не то, откуда её вызвали.**

Это называется лексической областью видимости. При создании функции к ней «прикрепляется» ссылка на внешнее окружение — набор переменных, которые её окружали.

```javascript
const lang = "глобальный";

function outer() {
    const lang = "из outer";
    return function inner() {
        console.log(lang);  // смотрит туда, где inner была ОБЪЯВЛЕНА
    };
}

const fn = outer();
fn(); // "из outer" — хотя вызвали её из глобальной области
```

**Замыкание (closure)** — функция вместе с сохранённым внешним окружением. Пока живёт функция, живут и переменные, которые ей нужны: сборщик мусора не удалит их, даже если внешняя функция давно завершилась.

В JavaScript замыкание образует **каждая** функция — просто обычно мы этого не замечаем.

## 4. Счётчик — канонический пример

```javascript
function makeCounter() {
    let count = 0;            // переменная живёт в замыкании

    return function () {
        count++;
        return count;
    };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3

console.log(count); // ❌ ReferenceError — снаружи переменной нет
```

Разберём, что произошло:
1. `makeCounter()` создала переменную `count` и вернула функцию;
2. внешняя функция завершилась, но `count` не исчезла — на неё ссылается возвращённая функция;
3. каждый вызов `counter()` работает с той же самой `count`.

**Каждый вызов внешней функции создаёт НОВОЕ независимое замыкание:**

```javascript
const counterA = makeCounter();
const counterB = makeCounter();

console.log(counterA()); // 1
console.log(counterA()); // 2
console.log(counterB()); // 1 — у B своя count, счётчики не связаны
```

Это как две коробки, собранные по одному чертежу: устройство общее, содержимое у каждой своё.

## 5. Приватные данные

Из урока 8 первого курса вы помните: свойства объекта доступны снаружи, испортить их может кто угодно.

```javascript
const account = { balance: 100000 };
account.balance = -999999; // никто не помешал
```

Замыкание даёт настоящую приватность — к переменной нельзя добраться иначе, чем через предоставленные функции:

```javascript
function createAccount(owner, startBalance = 0) {
    let balance = startBalance;   // приватная переменная

    return {
        deposit(sum) {
            if (sum <= 0) {
                console.log("Сумма должна быть больше нуля");
                return;
            }
            balance += sum;
            return balance;
        },
        withdraw(sum) {
            if (sum > balance) {
                console.log("Недостаточно средств");
                return;
            }
            balance -= sum;
            return balance;
        },
        check() {
            return `${owner}: ${balance.toLocaleString("ru-RU")} сум`;
        }
    };
}

const acc = createAccount("Али", 100000);
acc.deposit(50000);
console.log(acc.check());   // "Али: 150 000 сум"

console.log(acc.balance);   // undefined — свойства нет
acc.balance = -999999;      // создали постороннее свойство, на баланс не влияет
console.log(acc.check());   // "Али: 150 000 сум" — данные защищены
```

Это тот самый «Банкомат» из первого курса — теперь у приёма есть имя. Такая конструкция называется **модульным паттерном**: наружу выставлены только методы, состояние спрятано.

### IIFE — функция, вызванная сразу

Иногда замыкание нужно один раз и без имени. Тогда функцию объявляют и тут же вызывают:

```javascript
const config = (function () {
    const apiKey = "секрет";        // снаружи недоступен
    let requests = 0;

    return {
        makeRequest() {
            requests++;
            return `Запрос №${requests} с ключом ${apiKey}`;
        }
    };
})();  // ← скобки в конце вызывают функцию немедленно

console.log(config.makeRequest()); // "Запрос №1 с ключом секрет"
console.log(config.apiKey);        // undefined
```

`IIFE` — Immediately Invoked Function Expression, «немедленно вызываемое функциональное выражение». До появления модулей (раздел 4) так изолировали код целых библиотек. Сегодня встречается в основном в чужом коде — важно узнавать.

## 6. Замыкания в работе

### Фабрика функций

```javascript
function multiplier(factor) {
    return n => n * factor;
}

const double = multiplier(2);
const triple = multiplier(3);
const withVat = multiplier(1.12);

console.log(double(10));     // 20
console.log(triple(10));     // 30
console.log(withVat(50000)); // 56000.00000000001
```

Одна фабрика — сколько угодно специализированных функций.

### Выполнить только один раз

```javascript
function once(fn) {
    let called = false;
    let result;

    return function (...args) {          // rest из урока 9 первого курса
        if (called) {
            return result;
        }
        called = true;
        result = fn(...args);
        return result;
    };
}

const register = once(name => {
    console.log("Регистрируем", name);
    return `Пользователь ${name} создан`;
});

console.log(register("Али"));  // "Регистрируем Али" → "Пользователь Али создан"
console.log(register("Вали")); // "Пользователь Али создан" — повторно не выполнилось
```

Так защищают от двойной отправки формы по двойному клику.

### Мемоизация — запоминание результатов

```javascript
function memoize(fn) {
    const cache = {};                 // хранилище в замыкании

    return function (n) {
        if (n in cache) {             // оператор in из урока 8
            console.log("из кэша");
            return cache[n];
        }
        const result = fn(n);
        cache[n] = result;
        return result;
    };
}

const slowSquare = n => {
    for (let i = 0; i < 1e8; i++) {}  // имитация долгих вычислений
    return n * n;
};

const fastSquare = memoize(slowSquare);

console.log(fastSquare(9)); // считает долго → 81
console.log(fastSquare(9)); // "из кэша" → 81 мгновенно
```

## 7. Ловушка: замыкание в цикле

Классическая задача с собеседований. Что выведет код?

```javascript
const fns = [];

for (var i = 0; i < 3; i++) {
    fns.push(function () {
        console.log(i);
    });
}

fns.forEach(fn => fn());
```

Ожидание — `0 1 2`. Реальность — **`3 3 3`**.

Причина в `var` (урок 10 первого курса): у него нет блочной области видимости, поэтому `i` **одна на весь цикл**. Все три функции замкнулись на одну и ту же переменную, а к моменту вызова она давно равна 3.

С `let` всё работает как ожидается:

```javascript
for (let i = 0; i < 3; i++) {
    fns.push(() => console.log(i));
}
// 0 1 2 — let создаёт НОВУЮ переменную на каждой итерации,
// и каждая функция замыкается на свою
```

Вот и ещё один аргумент против `var` — теперь понятный до конца.

## 8. Замыкания вокруг нас

Вы пользовались ими весь первый курс, не зная названия:

```javascript
const limit = 100;
const cheap = prices.filter(p => p < limit);   // колбэк замкнулся на limit

const name = "Али";
btn.addEventListener("click", () => {
    console.log(`Привет, ${name}`);            // обработчик замкнулся на name
});
```

Именно поэтому обработчик события, назначенный один раз, помнит переменные из момента подписки. В третьем разделе это станет ещё важнее: асинхронный код выполняется позже, а данные ему нужны те, что были в момент запуска.

## Вопросы с собеседований 💼

<details>
<summary><b>1. Что такое замыкание?</b></summary>

Замыкание — функция вместе с сохранённым внешним лексическим окружением. Функция запоминает переменные того места, где была объявлена, и продолжает иметь к ним доступ даже после того, как внешняя функция завершилась. В JavaScript замыкание образует каждая функция, просто чаще всего это незаметно.
</details>

<details>
<summary><b>2. Что такое функция высшего порядка?</b></summary>

Функция, которая принимает другую функцию как аргумент и/или возвращает функцию. Примеры из стандартной библиотеки — `map`, `filter`, `reduce`, `addEventListener`. Это возможно потому, что функции в JS — обычные значения, которые можно передавать и возвращать.
</details>

<details>
<summary><b>3. Зачем нужны замыкания на практике?</b></summary>

Приватные данные и модульный паттерн (состояние спрятано, наружу выставлены методы), фабрики функций (`multiplier(2)`), мемоизация и кэширование, функции-обёртки вроде `once`, `debounce`, `throttle`, а также счётчики и любое сохранение состояния между вызовами без глобальных переменных.
</details>

<details>
<summary><b>4. Будут ли счётчики, созданные одной фабрикой, независимы?</b></summary>

Да. Каждый вызов внешней функции создаёт новое лексическое окружение, поэтому у каждого счётчика своя переменная. Общим устройство остаётся только «по чертежу», данные не пересекаются.
</details>

<details>
<summary><b>5. Что такое IIFE и зачем оно нужно?</b></summary>

Immediately Invoked Function Expression — функция, которая объявляется и тут же вызывается: `(function () { … })()`. Создаёт изолированную область видимости, чтобы переменные не попали в глобальную. До появления ES-модулей это был основной способ изолировать код библиотеки; сегодня используется редко, но часто встречается в старом коде.
</details>

<details>
<summary><b>6. Могут ли замыкания привести к утечке памяти?</b></summary>

Да. Пока существует функция-замыкание, сборщик мусора не может освободить переменные, на которые она ссылается. Если такая функция висит в долгоживущем обработчике события или в таймере и удерживает большой объект, память не освободится. Лечится снятием обработчика и очисткой ссылок, когда они больше не нужны.
</details>

<details>
<summary><b>7. Практическая задача: почему выводится 3 3 3 и как починить?</b>

```javascript
const fns = [];
for (var i = 0; i < 3; i++) {
    fns.push(() => console.log(i));
}
fns.forEach(fn => fn());
```
</summary>

`var` не имеет блочной области видимости — переменная `i` одна на весь цикл, и все три функции замкнулись именно на неё. К моменту вызова цикл давно закончился и `i` равна 3. Починка: заменить `var` на `let` — тогда на каждой итерации создаётся отдельная переменная и каждая функция замыкается на свою копию. Исторический вариант до ES6 — обернуть тело цикла в IIFE с параметром.
</details>
