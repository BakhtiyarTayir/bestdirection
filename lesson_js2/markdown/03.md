## 1. setTimeout — выполнить позже

```javascript
setTimeout(function () {
    console.log("Прошла секунда");
}, 1000);

console.log("Эта строка выведется ПЕРВОЙ");
```

Вывод: сначала «Эта строка выведется ПЕРВОЙ», через секунду — «Прошла секунда».

Первый аргумент — функция (снова колбэк из урока 14 первого курса), второй — задержка в **миллисекундах**: 1000 мс = 1 секунда.

Программа не останавливается и не ждёт: она регистрирует задачу «выполнить это позже» и идёт дальше. Это первое знакомство с асинхронностью — подробно разберём её в третьем разделе.

Аргументы для колбэка передаются третьим и далее:

```javascript
function greet(name, greeting) {
    console.log(`${greeting}, ${name}!`);
}
setTimeout(greet, 2000, "Али", "Салом");   // "Салом, Али!" через 2 секунды
```

⚠️ Частая ошибка — вызвать функцию вместо того, чтобы передать её:

```javascript
setTimeout(greet("Али", "Салом"), 2000);  // ❌ выполнится немедленно
setTimeout(() => greet("Али", "Салом"), 2000); // ✅
```

Та же ловушка, что с колбэками в `map` и `forEach`: скобки означают вызов.

## 2. clearTimeout — отменить

`setTimeout` возвращает идентификатор таймера — по нему запланированное можно отменить, пока оно не выполнилось:

```javascript
const timerId = setTimeout(() => console.log("Не увидите"), 3000);
clearTimeout(timerId);   // отменили
```

Реальный пример — «отправляем через 5 секунд, но можно отменить»:

```javascript
let sendId = null;

sendBtn.addEventListener("click", () => {
    status.innerText = "Отправка через 5 секунд…";
    sendId = setTimeout(() => {
        status.innerText = "Отправлено";
        sendId = null;
    }, 5000);
});

cancelBtn.addEventListener("click", () => {
    clearTimeout(sendId);
    status.innerText = "Отменено";
});
```

## 3. setInterval — повторять

```javascript
const intervalId = setInterval(() => {
    console.log("тик");
}, 1000);
```

Работает **бесконечно**, пока не остановят:

```javascript
clearInterval(intervalId);
```

Классический счётчик с остановкой:

```javascript
let count = 5;

const id = setInterval(() => {
    console.log(count);
    count--;

    if (count === 0) {
        clearInterval(id);      // ← без этого цикл никогда не кончится
        console.log("Поехали! 🚀");
    }
}, 1000);
```

**Всегда сохраняйте id и всегда предусматривайте условие остановки** — забытый интервал так же опасен, как бесконечный цикл `while` из первого курса: он продолжает работать, даже когда элемент, ради которого запускался, уже удалён со страницы.

## 4. Задержка — это «не раньше чем»

```javascript
setTimeout(() => console.log("Я"), 0);
console.log("сначала");
// сначала
// Я
```

Даже с нулевой задержкой колбэк выполнится **после** текущего кода. JavaScript однопоточен: сначала доделывается всё, что выполняется сейчас, и только потом берётся отложенная задача.

Отсюда следствие: если основной код занят тяжёлым циклом, таймер опоздает.

```javascript
setTimeout(() => console.log("должен был через 100 мс"), 100);
for (let i = 0; i < 1e9; i++) {}   // блокируем поток на секунды
// колбэк выполнится только после цикла
```

**Задержка гарантирует минимум, а не точность.** Почему это так устроено — тема урока про event loop в третьем разделе.

Практический вывод: не полагайтесь на `setInterval` при отсчёте времени. Секундомер, который просто прибавляет по единице каждые 1000 мс, за минуту заметно уплывёт. Правильно — запомнить время старта и каждый тик считать разницу:

```javascript
const start = Date.now();                // миллисекунды с 1970 года

setInterval(() => {
    const seconds = Math.floor((Date.now() - start) / 1000);
    console.log(seconds);                // всегда точно
}, 1000);
```

## 5. Рекурсивный setTimeout

Второй способ повторения — таймер, который в конце планирует сам себя:

```javascript
function tick() {
    console.log("тик");
    setTimeout(tick, 1000);
}
setTimeout(tick, 1000);
```

Чем он лучше `setInterval`:

| | setInterval | рекурсивный setTimeout |
|---|-------------|------------------------|
| Отсчёт паузы | от старта предыдущего запуска | после завершения предыдущего |
| Долгий колбэк | вызовы «слипаются», очередь копится | пауза всегда соблюдается |
| Изменить задержку на ходу | нельзя | можно на каждом шаге |

Если колбэк выполняется дольше интервала, `setInterval` продолжает ставить вызовы в очередь — они пойдут подряд без пауз. Рекурсивный `setTimeout` такого не допускает, поэтому для сетевых опросов (третий раздел) используют именно его.

## 6. this в таймере

Помните потерю контекста из урока 2? Таймер — её главный источник:

```javascript
const user = {
    name: "Али",
    greetLater() {
        setTimeout(function () {
            console.log("Привет, " + this.name);   // ❌ undefined
        }, 1000);
    }
};
user.greetLater();
```

Колбэк вызывается таймером обычным вызовом, объект теряется. Починка та же — стрелочная функция:

```javascript
greetLater() {
    setTimeout(() => console.log("Привет, " + this.name), 1000);  // ✅
}
```

Отдельная ловушка — передать метод напрямую:

```javascript
setTimeout(user.greetLater, 1000);            // ❌ контекст потерян
setTimeout(() => user.greetLater(), 1000);    // ✅
setTimeout(user.greetLater.bind(user), 1000); // ✅
```

## 7. debounce — «подожди, пока перестанут»

Задача: поле поиска. Пользователь печатает «телефон» — событие `input` срабатывает 7 раз. Делать 7 запросов не нужно, нужен один — когда человек закончил печатать.

**Debounce** откладывает вызов и сбрасывает отсчёт при каждом новом событии. Функция выполнится, только когда наступит тишина заданной длины.

```javascript
function debounce(fn, delay) {
    let timerId = null;                  // живёт в замыкании (урок 1)

    return function (...args) {
        clearTimeout(timerId);           // отменяем предыдущий план
        timerId = setTimeout(() => fn(...args), delay);
    };
}

const search = (text) => console.log("Ищем:", text);
const debouncedSearch = debounce(search, 500);

input.addEventListener("input", (event) => {
    debouncedSearch(event.currentTarget.value);
});
// печатаем «телефон» → один вызов через 500 мс после последней буквы
```

Обратите внимание, как складываются темы раздела: замыкание хранит `timerId`, стрелочная функция сохраняет контекст, таймер откладывает вызов.

Где применяют: живой поиск, автосохранение черновика, валидация во время ввода, реакция на `resize` окна.

## 8. throttle — «не чаще, чем раз в N»

Задача другая: обработчик прокрутки срабатывает сотни раз в секунду. Ждать тишины нельзя — нужно реагировать, но реже.

**Throttle** пропускает вызов и на заданное время блокирует следующие.

```javascript
function throttle(fn, delay) {
    let isWaiting = false;

    return function (...args) {
        if (isWaiting) {
            return;                       // ещё рано — игнорируем
        }
        fn(...args);
        isWaiting = true;
        setTimeout(() => { isWaiting = false; }, delay);
    };
}

const onScroll = () => console.log("Позиция:", window.scrollY);
window.addEventListener("scroll", throttle(onScroll, 300));
// при прокрутке — не чаще одного вызова в 300 мс
```

**Разница на одном примере.** Пользователь 10 раз подряд быстро нажал кнопку:

```
debounce(300):  ничего… ничего… ничего… → 1 вызов через 300 мс после последнего
throttle(300):  вызов сразу → пауза → вызов → пауза → …
```

| | debounce | throttle |
|---|----------|----------|
| Когда вызывает | после паузы в событиях | сразу и потом не чаще N мс |
| Сколько вызовов из серии | один, последний | несколько, равномерно |
| Типичные задачи | поиск, автосохранение, resize | scroll, mousemove, перетаскивание |

## Вопросы с собеседований 💼

<details>
<summary><b>1. Чем setTimeout отличается от setInterval?</b></summary>

`setTimeout` планирует одно выполнение через заданную задержку, `setInterval` — повторяет вызов каждые N миллисекунд, пока его не остановят через `clearInterval`. Оба возвращают идентификатор таймера, по которому его можно отменить.
</details>

<details>
<summary><b>2. Гарантирует ли setTimeout(fn, 100), что функция выполнится ровно через 100 мс?</b></summary>

Нет. Задержка означает «не раньше чем»: колбэк попадёт в очередь через 100 мс, но выполнится только тогда, когда освободится основной поток. Если в этот момент выполняется тяжёлый синхронный код, вызов опоздает. Даже `setTimeout(fn, 0)` выполняется после завершения текущего кода.
</details>

<details>
<summary><b>3. Чем рекурсивный setTimeout лучше setInterval?</b></summary>

`setInterval` отсчитывает паузу от старта предыдущего вызова, поэтому при долгом колбэке вызовы «слипаются» и идут подряд. Рекурсивный `setTimeout` планирует следующий запуск только после завершения текущего — пауза соблюдается всегда. Плюс он позволяет менять задержку на каждом шаге, что нужно, например, при повторных попытках запроса.
</details>

<details>
<summary><b>4. Что произойдёт, если не вызвать clearInterval?</b></summary>

Интервал продолжит работать до перезагрузки страницы — даже если элемент, ради которого он запускался, уже удалён. Это лишняя нагрузка и источник утечек памяти: колбэк держит замыкание со всеми переменными, на которые ссылается. Идентификатор интервала нужно сохранять и очищать, когда он больше не нужен.
</details>

<details>
<summary><b>5. Что такое debounce и throttle? В чём разница?</b></summary>

Обе техники ограничивают частоту вызовов. `debounce` откладывает вызов и сбрасывает отсчёт при каждом новом событии — функция сработает один раз, когда события прекратятся; подходит для поиска и автосохранения. `throttle` вызывает функцию сразу и затем блокирует вызовы на заданное время — она срабатывает регулярно, но не чаще N миллисекунд; подходит для scroll и mousemove.
</details>

<details>
<summary><b>6. Почему this внутри setTimeout не работает как ожидается?</b></summary>

Таймер вызывает переданный колбэк обычным вызовом, без объекта — срабатывает первое правило определения `this`, и контекст теряется. Решения: стрелочная функция (берёт `this` из окружения) или `bind` при передаче метода.
</details>

<details>
<summary><b>7. Практическая задача: что выведет код и почему?</b>

```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
for (let i = 0; i < 3; i++) {
    console.log(i);
}
console.log("C");
```
</summary>

`A`, `0`, `1`, `2`, `C`, `B`. Даже с нулевой задержкой колбэк не выполняется сразу: он попадает в очередь и берётся оттуда, только когда закончится весь текущий синхронный код. Поэтому `B` выводится последним, после цикла и после `C`.
</details>
