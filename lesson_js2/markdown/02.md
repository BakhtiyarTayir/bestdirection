# Урок 2. this и контекст вызова

## Цели урока

После этого урока студент:

## 1. Проблема

В уроке 8 первого курса мы договорились: `this` — это «текущий объект». Формулировка рабочая, но неполная. Смотрите:

```javascript
const user = {
    name: "Али",
    sayHi() {
        console.log("Привет, я " + this.name);
    }
};

user.sayHi();                 // "Привет, я Али" — работает

const greet = user.sayHi;     // взяли ту же функцию в переменную
greet();                      // "Привет, я undefined" 😱
```

Функция одна и та же. Меняется только способ вызова — и `this` меняется вместе с ним.

**Ключевое правило урока: `this` определяется НЕ там, где функция объявлена, а там, где она ВЫЗВАНА.**

Этим `this` отличается от обычных переменных: их функция берёт из лексического окружения (урок 1), а `this` получает заново при каждом вызове.

## 2. Четыре правила

Чтобы определить `this`, посмотрите на форму вызова.

### Правило 1. Обычный вызов — `this` не определён

```javascript
function show() {
    console.log(this);
}
show();  // undefined в модулях и strict mode; объект window — в обычном скрипте
```

В современном коде (модули из раздела 4 включают strict mode автоматически) это `undefined`. Отсюда и `this.name` → ошибка либо `undefined`.

### Правило 2. Вызов как метода — `this` это объект перед точкой

```javascript
const user = { name: "Али", sayHi() { console.log(this.name); } };
user.sayHi();  // "Али" — слева от точки user
```

Важно: значение имеет **только последняя точка перед скобками**.

```javascript
const app = {
    title: "LMS",
    admin: {
        title: "Панель",
        show() { console.log(this.title); }
    }
};

app.admin.show();  // "Панель" — this это admin, а не app
```

### Правило 3. Явная привязка — `call`, `apply`, `bind`

Мы сами говорим, каким будет `this` (раздел 4 урока).

### Правило 4. Вызов через `new` — новый объект

```javascript
function User(name) {
    this.name = name;
}
const u = new User("Али");
console.log(u.name); // "Али"
```

`new` создаёт пустой объект и делает его контекстом. Подробно — в разделе про классы; сейчас достаточно знать, что такая форма вызова существует.

**Шпаргалка: смотрите, что стоит слева от скобок вызова.**

| Форма вызова | Чему равен `this` |
|--------------|-------------------|
| `fn()` | `undefined` (strict) |
| `obj.fn()` | `obj` |
| `fn.call(obj)` / `fn.bind(obj)()` | `obj` |
| `new Fn()` | новый объект |
| стрелочная функция | берётся из внешнего кода, своего нет |

## 3. Потеря контекста: три сценария

### Сценарий 1. Метод передали как колбэк

```javascript
const timer = {
    name: "Таймер",
    start() {
        console.log(this.name + " запущен");
    }
};

[1].forEach(timer.start);   // "undefined запущен" 😱
```

`forEach` получил **саму функцию**, оторванную от объекта, и вызвал её обычным вызовом — сработало правило 1. То же самое случится с `addEventListener(..., user.handle)` и с таймерами из следующего урока.

Починка — обернуть в стрелочную функцию, чтобы вызов остался «через точку»:

```javascript
[1].forEach(() => timer.start());  // ✅ "Таймер запущен"
```

### Сценарий 2. Вложенная обычная функция

```javascript
const cart = {
    items: ["Телефон", "Наушники"],
    showAll() {
        this.items.forEach(function (item) {
            console.log(this.items.length, item); // ❌ TypeError
        });
    }
};
```

Внешний метод вызван правильно, но колбэк внутри — обычная функция, у неё свой `this` по правилу 1. Починка — стрелочная функция: у неё нет собственного `this`, и она берёт его из `showAll`:

```javascript
showAll() {
    this.items.forEach(item => {
        console.log(this.items.length, item);  // ✅
    });
}
```

### Сценарий 3. Стрелочная функция как метод объекта

Обратная ошибка — ею мы уже пугались в первом курсе:

```javascript
const user = {
    name: "Али",
    sayHi: () => console.log(this.name)  // ❌ "undefined"
};
```

У стрелки нет своего `this`, она берёт его из окружающего кода — а вокруг объекта лежит глобальная область, а не сам объект. **Методы объекта пишем обычными функциями.**

## 4. call, apply и bind

Все три позволяют задать `this` явно. Разница — в моменте и в форме аргументов.

```javascript
function introduce(city, job) {
    console.log(`${this.name}, ${city}, ${job}`);
}

const ali = { name: "Али" };
const gulya = { name: "Гуля" };

introduce.call(ali, "Ташкент", "разработчик");     // аргументы через запятую
introduce.apply(gulya, ["Самарканд", "дизайнер"]); // аргументы массивом
```

`call` и `apply` **вызывают функцию сразу**. Отличаются только тем, как передаются аргументы: «call — Comma, apply — Array».

`bind` ничего не вызывает — он **создаёт новую функцию** с намертво привязанным контекстом:

```javascript
const introduceAli = introduce.bind(ali);
introduceAli("Ташкент", "разработчик");  // "Али, Ташкент, разработчик"
```

Именно `bind` спасает в сценарии 1:

```javascript
const timer = { name: "Таймер", start() { console.log(this.name); } };

[1].forEach(timer.start);            // "undefined"
[1].forEach(timer.start.bind(timer)); // "Таймер" ✅
```

Привязка окончательная: повторный `bind` или вызов через `call` уже ничего не изменят.

```javascript
const bound = introduce.bind(ali);
bound.call(gulya, "Бухара", "тестировщик"); // всё равно "Али, …"
```

Аргументы тоже можно привязать заранее — это называется частичным применением:

```javascript
const withVat = ((rate, sum) => sum * rate).bind(null, 1.12);
console.log(withVat(50000)); // 56000.00000000001
```

## 5. this в обработчиках событий

В обработчике, объявленном **обычной** функцией, `this` — это элемент, на котором висит обработчик:

```javascript
btn.addEventListener("click", function () {
    console.log(this);           // сам элемент <button>
    this.classList.toggle("active");
});
```

В **стрелочной** — `this` берётся снаружи, поэтому элемент нужно брать из события:

```javascript
btn.addEventListener("click", (event) => {
    console.log(this);                    // НЕ кнопка
    event.currentTarget.classList.toggle("active");  // ✅ так надёжнее
});
```

**Практический совет:** пишите обработчики стрелочными и обращайтесь к элементу через `event.currentTarget` — тогда поведение одинаково и внутри объекта, и снаружи. К разнице `target` и `currentTarget` вернёмся в уроке про делегирование.

## 6. Когда какая функция

| | обычная функция | стрелочная |
|---|-----------------|------------|
| Свой `this` | есть, зависит от вызова | нет, берёт из окружения |
| Метод объекта | ✅ да | ❌ нет |
| Колбэк внутри метода | ❌ теряет контекст | ✅ да |
| Обработчик события | `this` = элемент | элемент через `event.currentTarget` |
| `call` / `apply` / `bind` | работают | контекст не меняют |
| Объект `arguments` | есть | нет, используйте `...rest` |

Короткое правило: **метод объекта — обычная функция, всё, что внутри метода, — стрелочная.**

## Вопросы с собеседований 💼

<details>
<summary><b>1. Что такое this и когда оно определяется?</b></summary>

`this` — ссылка на контекст выполнения функции. Определяется в момент ВЫЗОВА, а не при объявлении: одна и та же функция при разных формах вызова получит разный `this`. Этим он отличается от обычных переменных, которые берутся из лексического окружения.
</details>

<details>
<summary><b>2. Перечислите правила определения this.</b></summary>

Обычный вызов `fn()` — `undefined` в strict mode (в нестрогом — глобальный объект). Вызов как метода `obj.fn()` — объект перед последней точкой. Явная привязка `call`/`apply`/`bind` — переданный объект. Вызов через `new` — новый создаваемый объект. Отдельно: у стрелочных функций своего `this` нет, они берут его из окружающего кода.
</details>

<details>
<summary><b>3. В чём разница между call, apply и bind?</b></summary>

`call` и `apply` вызывают функцию немедленно с указанным контекстом; отличаются формой передачи аргументов: `call` — через запятую, `apply` — массивом. `bind` не вызывает функцию, а возвращает новую с навсегда привязанным контекстом (и, если нужно, с заранее подставленными аргументами).
</details>

<details>
<summary><b>4. Что такое потеря контекста? Приведите пример.</b></summary>

Ситуация, когда метод отрывают от объекта и вызывают отдельно — контекст перестаёт быть объектом. Классика: `setTimeout(user.greet, 1000)` или `arr.forEach(user.greet)` — метод передан как значение и вызывается обычным вызовом, поэтому `this` внутри не объект. Лечится обёрткой в стрелочную функцию или `bind`.
</details>

<details>
<summary><b>5. Почему методы объекта не пишут стрелочными функциями?</b></summary>

У стрелочной функции нет собственного `this` — она берёт его из окружающего лексического окружения. Для метода, объявленного прямо в литерале объекта, окружением будет внешний код, а не сам объект, поэтому `this.name` даст undefined. Обратная ситуация — колбэк внутри метода: там стрелочная функция как раз нужна, чтобы унаследовать `this` метода.
</details>

<details>
<summary><b>6. Чему равен this в обработчике события?</b></summary>

В обработчике-обычной функции `this` — это элемент, на котором висит обработчик (то же, что `event.currentTarget`). В стрелочном обработчике `this` берётся из внешнего кода, поэтому к элементу обращаются через `event.currentTarget`. Второй вариант предсказуемее и работает одинаково в любом окружении.
</details>

<details>
<summary><b>7. Практическая задача: что выведет код?</b>

```javascript
const shop = {
    name: "Магазин",
    products: ["A", "B"],
    showRegular() {
        this.products.forEach(function (p) {
            console.log(this?.name, p);
        });
    },
    showArrow() {
        this.products.forEach(p => console.log(this.name, p));
    }
};
shop.showRegular();
shop.showArrow();
```
</summary>

`showRegular` выведет `undefined A` и `undefined B`: колбэк — обычная функция, вызванная внутри forEach обычным вызовом, поэтому у неё свой `this`, равный undefined. `showArrow` выведет `Магазин A` и `Магазин B`: у стрелочной функции своего `this` нет, она берёт его у метода `showArrow`, а тот вызван через точку от `shop`.
</details>
