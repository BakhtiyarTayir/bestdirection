# План: главная панель (дашборд) по ролям — 2026-09-23

Владелец попросил сделать главную полезной. Сейчас там только счётчики
(пользователи, курсы, преподаватели, ученики). Делаем три независимые части —
администратор, преподаватель, ученик/родитель — тремя агентами параллельно.

## 0. Общие правила для всех частей

- **Форма, а не графики** (навык dataviz): одна главная цифра, ряд коротких
  показателей (stat tiles), затем списки «что сделать». Графиков пока нет:
  данных о деньгах всего за один месяц (сентябрь 2026), тренд появится через
  3–4 месяца — это отдельная будущая задача.
- **Каждая карточка — ссылка** в свой раздел (компонент `StatCard` в
  `src/app/[locale]/(dashboard)/dashboard/page.tsx` уже умеет `href`).
- **Статус — цветом + иконкой + текстом**, никогда одним цветом (например,
  «не отмечено» — жёлтый значок `TriangleAlert` + подпись).
- **«Сегодня» и «текущий месяц» — по Ташкенту**: `currentMonthKey()` из
  `api/src/modules/billing/domain/billing.ts`; сегодняшняя дата по Ташкенту —
  дата от `now + 5 часов` (посмотри, как устроен `currentMonthKey`, и сделай
  рядом `currentDateKey(): "YYYY-MM-DD"` + `isoWeekday` для дня недели, если
  его ещё нет — не дублируй, если другой агент уже добавил: ты в своей копии
  репозитория, поэтому просто добавь; конфликт при слиянии разрешит старший
  инженер).
- **Деньги видит только администратор.** Преподаватель — только свою
  зарплату (как `/salary/me`), ученик/родитель — только свой баланс (свой или
  своих детей). Проверь права тестом: чужое — 403/404.
- **Своя часть — свои файлы**, чтобы три ветки сливались без боли:
  - API: свой контроллер с префиксом `dashboard/<часть>` и свой сервис в
    `api/src/modules/dashboard/` (Nest допускает несколько контроллеров в
    модуле). Общие файлы (`dashboard.module.ts`) правь минимально.
  - Web: свой серверный компонент в
    `src/app/[locale]/(dashboard)/dashboard/<часть>-dashboard.tsx` и
    клиентские куски в `src/components/dashboard/<часть>/`. В `page.tsx`
    меняй ТОЛЬКО ветку своей роли — заменить её вызовом своего компонента.
  - Переводы: свой namespace верхнего уровня в `src/i18n/messages/ru.json` и
    `uz.json`: `dashboardAdmin` / `dashboardTeacher` / `dashboardStudent`.
    Узбекский — латиница, как во всём файле.
- **Телефон**: всё должно нормально выглядеть на ширине 360px (сетка
  `grid gap-4 md:grid-cols-2 lg:grid-cols-4`, таблицы — в `overflow-x-auto`).
- Тесты: e2e в `api/test/dashboard-<часть>.e2e-spec.ts` (Testcontainers), по
  образцу `api/test/finance.e2e-spec.ts` — свои данные в своём филиале.

## 1. Администратор (агент A)

API: `GET /dashboard/admin?branchId=` (`ability.can("manage", "Billing")`).

### 1.1 Деньги за текущий месяц (ряд из 4 карточек)
| Карточка | Откуда | Ссылка |
|---|---|---|
| Принято оплат + сравнение с прошлым месяцем (±%) | `FinanceService.overview` (`current.received`, прошлый месяц из `months`) | `/payments?month=` |
| Долг учеников: сумма и число должников | `BillingService.debtors({ branchId })` → `totalDebt`, `debtors.length` | `/payments/debtors` |
| Долг центра перед преподавателями | `SalaryService.overview(...)` → `totals.debt` (нужен actor-админ — передай его) | `/salaries` |
| Прибыль по кассе за месяц | `FinanceService.overview` → `current.cashProfit` | `/finance` |

`FinanceService` сейчас не экспортируется — добавь `exports: [FinanceService]`
в `finance.module.ts`. Не пересчитывай деньги своим кодом — только через эти
сервисы, иначе цифры на главной разойдутся со страницами.

### 1.2 «Сегодня» — занятия по расписанию
Группы, у которых сегодня (по Ташкенту) день занятий: `isActive`,
`scheduleDays` содержит ISO-день недели, `startDate` пусто или ≤ сегодня,
`endDate` пусто или ≥ сегодня, курс не в Корзине, фильтр филиала. По каждой:
группа, курс, филиал, преподаватель (`group.teacher ?? course.teacher`),
расписание текстом (`group.schedule`), **отмечено ли** — есть ли
`AttendanceSession` с `groupId` и `date` = сегодня. Ссылка — на журнал группы
(найди маршрут журнала посещаемости в `src/app/[locale]/(dashboard)/attendance`
или курсе). Сверху — итог «отмечено N из M».

### 1.3 «Требует внимания» (список с числами и ссылками; нули не показывать)
- Заявки на курсы в статусе PENDING (`EnrollmentRequest.status`) → `/courses/requests`.
- Заявки с сайта без отметки «связались» (`CourseLead.contacted = false`) → `/admin/leads`.
  У заявок нет филиала — при фильтре по филиалу этот пункт не фильтруется (пометь в коде).
- Ученики без группы: `Enrollment` с `groupId = null`, `unenrolledAt = null`,
  курс не в Корзине → им ничего не начисляется (цена только у групп) → `/students`.
- Группы без ставки зарплаты: активные группы, у которых `salaryPercentBp` пусто
  и у ведущего (`group.teacherId ?? course.teacherId`) личная ставка пусто → `/groups`.
- Группы с неполным журналом за текущий месяц: занятий по расписанию с начала
  месяца (или `startDate` группы) по сегодня включительно (`countLessons` из
  billing.ts) больше, чем записей `AttendanceSession` группы за этот период.
  Показать число групп; это важно — из-за неполного журнала замены не
  попадают в зарплату (правило «вариант А», `salary/domain/salary.ts`).

### 1.4 Фильтр по филиалу
`BranchFilter` (`src/components/branch-filter.tsx`, namespace `dashboardAdmin`
— добавь туда `filterBranch`/`allBranches`) над всем экраном; `branchId` в URL.

### 1.5 Справочные счётчики
Нынешние четыре карточки (пользователи, курсы, преподаватели, ученики) —
вторым рядом, ниже; они уже кликабельные.

## 2. Преподаватель (агент B)

API: `GET /dashboard/teacher` (роль TEACHER; администратору — 403 или пусто,
на твоё усмотрение, но проверь тестом). «Мои группы» = `group.teacherId = я`
ИЛИ (`group.teacherId` пусто И `course.teacherId = я`); только активные группы
курсов не из Корзины.

- **Мои занятия сегодня**: как 1.2, только мои группы; у каждого — «отмечено /
  не отмечено» и ссылка открыть журнал этой группы.
- **Неотмеченные занятия за месяц**: по каждой моей группе — даты занятий по
  расписанию с начала месяца (или `startDate`) по сегодня, на которые нет
  `AttendanceSession`. Список дат (формат DD.MM, `formatDate` из
  `src/lib/format-date.ts` не подходит — сделай короткий DD.MM) и пояснение
  одной строкой: «Пока журнал за месяц отмечен не полностью, замены не
  учитываются в зарплате».
- **Моя зарплата за месяц**: начислено за текущий месяц, выдано, долг — через
  `SalaryService.teacherDetail(me, { month }, actor)` (не пересчитывай сам).
  Карточка ведёт на `/salaries/me`.
- Нынешние карточки (мои курсы, ученики) оставь вторым рядом.

## 3. Ученик и родитель (агент C)

API: `GET /dashboard/student` (роли STUDENT и PARENT).

- **Ученик** (сам):
  - **Баланс**: долг или аванс на текущий месяц по каждому курсу и итог — через
    `BillingService.studentBilling(myId)` (не пересчитывай сам); показать
    только итог и по курсам: курс, цена в месяц, баланс (минус — долг,
    красным + подпись «долг»; плюс — «аванс»). Никаких чужих данных.
  - **Следующее занятие**: по каждой моей активной записи с группой —
    ближайшая дата ≥ сегодня по `scheduleDays` группы (с учётом
    `startDate`/`endDate`), название группы/курса, `group.schedule` текстом
    (там обычно время).
  - **Домашние задания со сроком**: задания уроков моих курсов с `dueDate` ≥
    сегодня, которые я ещё не сдал (посмотри модели Homework /
    HomeworkSubmission и как `/api/homework/count` считает несданные), по
    сроку, не больше 5, ссылка на урок.
  - Нынешние карточки (мои курсы, тесты) — вторым рядом.
- **Родитель**: по каждому ребёнку из `ParentStudent` — имя и те же три блока
  (баланс, следующее занятие, ближайшие задания). Если детей нет —
  подсказка «Администратор ещё не привязал ваших детей». Сейчас PARENT
  попадает в ветку ученика `forStudent` — раздели.
- Права: ученик видит только себя, родитель — только своих детей (тест:
  родитель не может получить чужого ребёнка, если маршрут принимает id).
