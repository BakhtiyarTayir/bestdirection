# План: родитель видит успеваемость ребёнка — 2026-09-24

Сейчас роль PARENT может только читать свой профиль (`abilities.ts`: «права на
данные детей появятся на этапе 3c»). Родитель видит список детей
(`/my-children`) и, с 2026-09-24, на главной — баланс, ближайшее занятие и
задания со сроком. Посещаемости, оценок и результатов тестов он не видит.
Делаем двумя агентами параллельно: A — страница, B — уведомления.

## 0. Общие правила

- **Родитель — только своих детей.** Дети — через `ParentStudent` (parentId =
  я), как в `ParentsService.children` и `StudentDashboardService`. Любой
  маршрут, принимающий id ребёнка, обязан проверить связь и отвечать 404 на
  чужого (не 403 — ответ не должен подтверждать, что такой ученик есть).
  Проверить тестом.
- **Ученику — то же про себя** (страница успеваемости полезна и ему):
  STUDENT видит только себя.
- Сдачи, попытки и отметки — только по курсам, на которые ребёнок записан, и
  курсам не из Корзины; уроки не из Корзины (расширение мягкого удаления
  фильтрует только модель прямого запроса — вложенные связи руками, как в
  `dashboard.service.ts`).
- Даты «сегодня/неделя» — по Ташкенту: `currentDateKey()` / `currentMonthKey()`
  в `api/src/modules/billing/domain/billing.ts`.
- Переводы — ru и uz (латиница), свой namespace, JSON правится без
  переформатирования файла (json.loads/json.dumps ensure_ascii=False indent=2,
  проверить `git diff --stat`).
- Телефон: всё читается на 360px.

## 1. Страница «Успеваемость» (агент A)

API `GET /progress/students/:studentId?from=&to=` (новый модуль
`api/src/modules/progress/`), доступ: PARENT — свой ребёнок, STUDENT — сам,
ADMIN — любой, TEACHER — ученик своих групп (лестница «педагог группы →
педагог курса», как `enrollmentTeacherFilter`). Период по умолчанию — текущий
месяц; выбор месяца.

Разделы ответа (по каждому курсу ребёнка):
1. **Посещаемость**: занятий в журнале за период, из них PRESENT / LATE /
   ABSENT / EXCUSED (`AttendanceRecord` ученика по `AttendanceSession` его
   группы), процент присутствия ((PRESENT+LATE)/всего), список дат пропусков
   (ABSENT) — DD.MM.
2. **Домашние задания**: задания уроков курса (`Homework`, опубликованные) с
   последней сдачей ученика (`Submission`: статус, оценка `score`/`percentage`,
   `reviewedAt`, комментарий преподавателя — посмотри поле отзыва в схеме), и
   «не сдано» для заданий со сроком в прошлом без сдачи. Итог: сдано N из M,
   средний процент по проверенным.
3. **Тесты**: завершённые попытки (`AssessmentAttempt.completedAt` не пусто) —
   тест, дата, процент; по каждому тесту лучшая попытка.
4. **Прогресс по урокам**: пройдено уроков (`LessonProgress.completedAt`) из
   опубликованных уроков курса.

Web:
- Страница `/my-children/[studentId]/progress` (родитель) и `/progress`
  (ученик — про себя); из карточки ребёнка на `/my-children` — кнопка
  «Успеваемость»; на главной родителя (`src/components/dashboard/student/`) —
  ссылка у каждого ребёнка. У администратора — кнопка «Успеваемость» в
  карточке ученика (`/payments/students/[studentId]` или профиль ученика —
  выбери, где уместнее, опиши). Пункт меню «Успеваемость» для STUDENT.
- Вид: сверху 3–4 плитки (посещаемость %, сдано заданий, средний балл за
  задания, средний балл за тесты), ниже блоки по курсам. Статусы — цвет +
  текст (не только цвет).
- Права в `abilities.ts`: добавь родителю ровно то, что нужно для этих
  данных, либо проверяй связь в сервисе явно — выбери и обоснуй; ничего
  сверх (родитель не должен получить доступ к спискам других учеников,
  журналам групп, оплатам других).

Тест `api/test/progress.e2e-spec.ts`: родитель видит своего и получает 404
на чужого; ученик — себя, не другого; преподаватель — ученика своей группы,
не чужой; цифры посещаемости/заданий/тестов на известных данных.

## 2. Telegram-уведомления родителям (агент B)

Отправка — `TelegramNotifyService.send(chatId, text)`
(`api/src/common/telegram/telegram-notify.service.ts`), адресаты — родители
ученика с привязанным Telegram (`User.telegramChatId`), через `ParentStudent`.
Нет Telegram — молча пропускаем. Ошибка отправки не должна ломать основное
действие (отметку, проверку задания) — отправка после записи, ошибки в лог.

Язык сообщения: посмотри, есть ли у пользователя сохранённый язык
интерфейса; если нет — узбекский (язык по умолчанию сайта, см.
`src/i18n/config.ts`). Тексты — в одном месте на API (объект ru/uz), не
размазывать по сервисам.

2.1 **Пропуск занятия**: когда в журнале ученику ставят ABSENT
   (`attendance.service.ts`, сохранение отметок) — родителям: «{Имя} не был(а)
   на занятии {группа}, {дата}». Только при переходе в ABSENT (не слать
   повторно при каждом сохранении того же журнала; повторная правка
   ABSENT→ABSENT — не событие). Если в течение того же сохранения статус
   сняли — не слать.
2.2 **Проверено домашнее задание**: когда преподаватель проверил сдачу
   (статус стал принятым / на доработку, появилась оценка — см.
   `homework/submissions.service.ts`) — родителям: задание, оценка/статус.
2.3 **Еженедельная сводка**: каждый понедельник 09:00 по Ташкенту
   (UTC 04:00) — родителям по каждому ребёнку за прошедшую неделю:
   посещаемость (было/пропуски), проверенные задания с оценками, пройденные
   тесты, долг по оплате если есть (через `BillingService.studentBilling`, не
   считать своим кодом). Планировщика в API нет — добавь `@nestjs/schedule`
   (в `api/package.json`; после `npm install` в `api/` проверь, что КОРНЕВЫЕ
   package.json/package-lock.json не изменились — известная ловушка проекта).
   Защита от двойной отправки при перезапуске контейнера в понедельник утром:
   запомни последнюю отправку (например, таблица/поле с датой недели) —
   предложи простой вариант и обоснуй. Выключатель: переменная окружения
   `PARENT_WEEKLY_DIGEST=off` отключает сводку.
2.4 Родитель может отключить уведомления: в боте команда `/stop` / `/start`
   или флаг у пользователя — выбери простой вариант (миграция только
   добавляет поле). Показать состояние в профиле родителя — по желанию.

Тесты: e2e на 2.1 и 2.2 (отправка замоканa — проверь, что вызвана с нужным
chatId и не вызвана для родителя без Telegram и для повторной ABSENT);
юнит на формирование текста сводки; сама отправка по расписанию — вызов
метода сводки напрямую в тесте.
