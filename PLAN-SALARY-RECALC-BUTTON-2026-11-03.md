# План: вернуть пересчёт зарплаты за закрытый месяц (2026-11-03)

## Зачем

Клиент нашёл расхождение у учителя Abrorov Shokhrux за октябрь 2026: сайт показал
2 988 400, по формуле 40 % выходит 2 829 200. Причина — в журнале группы
«1-guruh Elementary» 16 отметок при 14 занятиях по расписанию. Две лишние
отметки засчитаны как отработки (+2 × 79 600 = 159 200).

Если удалить лишние отметки, сумма сама не изменится: октябрь закрыт, начисление
заморожено (`TeacherSalaryAccrual`, `locked: true`). Нужен пересчёт. В API он есть
(`POST /salary/:teacherId/recalc`), а кнопку со страницы убрали 2026-10-23 вместе
с карточками групп (коммит `f195bec`).

## Что меняется для пользователя

На странице `/salaries/[teacherId]?month=YYYY-MM`, если месяц закрыт, рядом с
кнопками «Mukofot / jarima» и «To'lash» появляется кнопка **«Oyni qayta hisoblash»**.

По нажатию открывается окно подтверждения со списком групп учителя за этот месяц:

| Группа | Занятий по расписанию / отмечено | Сейчас начислено |
|---|---|---|

и пояснением: «Пересчёт возьмёт текущий журнал посещаемости. Цены учеников и
процент за месяц не меняются». Кнопки «Qayta hisoblash» и «Bekor qilish».

После подтверждения: пересчёт по всем группам месяца, тост «Было X → стало Y»
(или «Ничего не изменилось»), обновление страницы.

Для открытого (текущего) месяца кнопки нет: он и так считается по свежим данным.

## Почему одна кнопка, а не по группе

Разбивку по группам с этой страницы убрали по решению владельца 2026-10-23 —
возвращать её ради кнопки не нужно. Админу важен итог учителя за месяц; пересчёт
всех групп разом даёт ровно его. Список групп показывается только в окне
подтверждения, чтобы было видно, что поменяется.

## Работа

### web (основное)

1. `src/app/[locale]/(dashboard)/salaries/[teacherId]/page.tsx` — передать во view
   признак «месяц закрыт» и по каждой группе месяца: `groupId`, `courseId`, подпись
   группы, `lessonsPlanned`, `lessonsTaught`, `amount`. Всё это уже приходит в
   `getTeacherSalary` (`groups[].months`), новых запросов нет.
2. Новый компонент `recalc-month-button.tsx` рядом (по образцу удалённого
   `RecalcButton` из `f195bec` и кнопки в `payments/students/[studentId]/recalc-month-button.tsx`):
   окно подтверждения, последовательный вызов `recalculateSalaryMonth` по каждой
   группе, сумма до и после, тост, `router.refresh()`.
   Если одна группа упала — остальные не откатываются (каждый пересчёт —
   отдельная транзакция), тост называет группу с ошибкой.
3. `teacher-salary-view.tsx` — поставить кнопку рядом с «Mukofot / jarima».
4. Переводы `uz.json` / `ru.json`: часть ключей (`recalc`, `recalcTitle`,
   `recalcNoChange`, `recalcDone`) уже есть в разделе `salaries` — проверить и
   дописать недостающие (описание, «было → стало», ошибка по группе).

### api

Не меняется. `recalculateMonth` уже: только ADMIN, только закрытый месяц,
берёт свежий журнал, не трогает ручную сумму (`manualAmount`), пишет AuditLog,
покрыт `api/test/salary.e2e-spec.ts`.

## Проверка

- `npm run lint`, тайпчек web; `cd api && npm test` — для уверенности, что API цел.
- Локально: закрытый месяц с группой, где отметок больше расписания → удалить
  лишнюю отметку → кнопка → сумма уменьшилась на цену занятия; повторное нажатие →
  «Ничего не изменилось». Текущий месяц — кнопки нет. Учитель на `/salaries/me`
  кнопку не видит.
- Случай Шохруха НЕ трогаем (решение владельца 2026-11-05): отметки в журнале не
  удаляем, октябрь не пересчитываем, 2 988 400 остаётся как есть.

## Вне рамок

- Правило «отработки оплачиваются сверх 40 %» не меняем. Если клиент захочет
  строго 40 % при любом журнале — отдельное решение.
- Возврат разбивки по группам и ручной суммы на страницу — нет.
- Выплаты (`TeacherPayout`) пересчёт не трогает: уже выданный аванс 250 000
  остаётся, долг центра пересчитается от новой суммы.
