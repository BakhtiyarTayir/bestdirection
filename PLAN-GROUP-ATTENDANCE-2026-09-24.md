# План: журнал посещаемости по группам — 2026-09-24

## Сейчас
- **База уже по группам.** `AttendanceSession` имеет `courseId` и `groupId`
  (необязательный), уникальность `(courseId, date, groupId)` + частичный
  индекс для занятий без группы. На проде 2026-09-24: 3 занятия, все с группой.
  **Миграция данных не нужна.**
- **Интерфейс — от курса.**
  - Меню «Посещаемость» → `/attendance`: список курсов.
  - `/courses/[courseSlug]/attendance`: одна таблица `AttendanceGrid` — все
    занятия курса (всех групп вперемешку) × все ученики курса
    (`getEnrolledStudents(courseId)`).
  - `CreateSessionDialog` (`src/components/create-session-dialog.tsx`): группа
    «необязательна» (`groupOptional`).
  - Страница отметки `/courses/[courseSlug]/attendance/[sessionId]` уже
    сужает учеников до группы занятия.
- API: `GET /attendance/sessions?courseId=` (`attendance.service.ts` →
  `sessions`), `POST /attendance/sessions`, `PATCH .../records`,
  `GET /attendance/report?courseId=`.
- Ссылки «открыть журнал» ведут на журнал курса:
  `src/components/dashboard/admin/today-schedule.tsx`,
  `src/components/dashboard/teacher/schedule-tabs.tsx`,
  `src/components/dashboard/teacher/unmarked-list.tsx`.

## Решения владельца (2026-09-24)
- У каждой группы — свой журнал.
- Страница курса остаётся **обзором с вкладками по группам**.

## Что сделать

### 1. API
- `GET /attendance/sessions` принимает `groupId` (и по-прежнему `courseId`):
  с `groupId` — занятия только этой группы. Права: как сейчас
  (`canManageCourseAttendance` / лестница «педагог группы → педагог курса»;
  ученик — только своя группа и свои отметки). Преподаватель видит журнал
  группы, если он её педагог или педагог курса.
- `POST /attendance/sessions`: **`groupId` обязателен**, если у курса есть
  группы (у курса без групп — по-прежнему без группы; таких курсов на проде
  нет, но не ломать). Группа должна принадлежать курсу — иначе 400.
- Отчёт `GET /attendance/report` — принимает `groupId` (ученики и занятия
  группы).
- Новое: `GET /attendance/groups?branchId=&teacherId=&month=` — список групп
  для раздела «Посещаемость»: группа, курс, филиал, преподаватель
  (`group.teacher ?? course.teacher`), занятий по расписанию с начала месяца
  (или `startDate`) по сегодня (`countLessons`, как в
  `api/src/modules/dashboard/admin-dashboard.service.ts` → неполный журнал),
  отмечено занятий, дата последнего занятия. Преподавателю — только свои
  группы (та же лестница). Только активные группы курсов не из Корзины.
- Тесты `api/test/attendance-groups.e2e-spec.ts`: занятие без группы у курса с
  группами — 400; группа чужого курса — 400; `sessions?groupId=` отдаёт только
  свою группу; преподаватель другой группы — 404/403 (как принято в модуле);
  список групп считает «отмечено N из M».

### 2. Журнал группы (новая страница)
- `/courses/[courseSlug]/groups/[groupId]/attendance` (рядом с карточкой
  группы; посмотри соседние `statistics` и `students`).
- Таблица `AttendanceGrid`: занятия этой группы × ученики этой группы
  (`getEnrolledStudents(courseId, groupId)` уже умеет `groupId`).
- Кнопка «Новое занятие» — `CreateSessionDialog` с зафиксированной группой
  (выбор группы скрыт), дата по умолчанию — сегодня по Ташкенту.
- Сверху: «Отмечено N из M занятий за месяц» и подсказка, что замены в
  зарплате учитываются только при полностью отмеченном месяце.
- Ссылка на журнал — в карточке группы (`groups/[groupId]/page.tsx`) и в
  списке групп (`src/components/groups/group-list.tsx`).

### 3. Раздел «Посещаемость» (`/attendance`)
- Вместо списка курсов — список групп (эндпоинт из п.1): группа, курс,
  филиал, преподаватель, «отмечено N из M», ссылка на журнал группы.
  Фильтры: филиал (`BranchFilter`), преподаватель (`TeacherFilter`,
  `src/components/teacher-filter.tsx`, только администратору), месяц.
  Пагинация по 20 (`usePagination` из `src/components/ui/list-pagination.tsx`).
- Пункт меню «По курсам» (`attendanceByCourse` в `sidebar.tsx`) →
  переименовать в «По группам» (ru/uz).

### 4. Страница курса — обзор с вкладками
- `/courses/[courseSlug]/attendance`: вкладки по группам курса
  (`Tabs`), в каждой — таблица журнала этой группы (тот же компонент, что в
  п.2, без дублирования кода) и ссылка «Открыть журнал группы». Смешанной
  таблицы больше нет. Выбранная вкладка — в URL (`?group=`), чтобы ссылку
  можно было переслать.
- `CreateSessionDialog` здесь — с обязательным выбором группы (по умолчанию —
  группа открытой вкладки).

### 5. Ссылки
Три ссылки из «Сейчас» (главная администратора, расписание и неотмеченные у
преподавателя) → на журнал группы. У этих компонентов уже есть `groupId` в
данных (проверь; если нет — добавь в ответ API дашборда).

### 6. Не делаем
- Перенос или склейку старых занятий — все 3 на проде уже с группой.
- Изменение схемы (`groupId` остаётся необязательным в базе — обязательность
  держит API, как у цены группы).
